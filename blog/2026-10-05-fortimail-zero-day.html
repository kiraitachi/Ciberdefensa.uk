Proxmox V-GHOST (CVE-2026-74580): Critical KVM Escape Vulnerability

A recently disclosed vulnerability in Proxmox VE, tracked as CVE-2026-74580 (V-GHOST), allows out-of-bounds host memory access through a stale vhost IOTLB metadata cache after a vring was reconfigured. This flaw affects Proxmox Virtual Environment (VE) versions and represents a serious risk for virtualized infrastructure.

The vulnerability stems from improper handling of vhost IOTLB metadata caching in the KVM subsystem. After a vring is reconfigured, stale IOTLB metadata remains cached, allowing an attacker to access out-of-bounds host memory — a condition that could lead to VM escape scenarios.

Proxmox kernels have been fixed since version 7.0.14-14, which includes the relevant patches for CVE-2026-74580. However, users running older Proxmox VE releases on unpatched kernels — particularly those using the 6.8 kernel series on PVE 8 — remain exposed.

The Proxmox support team has confirmed that the fix is included in kernel updates since at least 7.0.14-14. Organizations running Proxmox VE should verify their kernel versions using uname -r or check via apt changelog proxmox-kernel, and apply updates immediately.

Mitigation recommendations include upgrading to the latest Proxmox kernel (7.0.14-14 or later), reviewing VM isolation configurations, and monitoring for anomalous vhost or vring reconfiguration events in virtualized environments.

Key Takeaways:

  • CVE-2026-74580 (V-GHOST) is a critical vulnerability affecting Proxmox VE
  • The flaw allows out-of-bounds host memory access via stale vhost IOTLB metadata
  • Fixed in proxmox-kernel 7.0.14-14 and later
  • Older PVE installations, especially with 6.8 kernel series, may remain vulnerable
  • Immediate patching is strongly recommended
